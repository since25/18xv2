# 待审核页面使用说明

快捷键或手动投递的路径会先落在「待审核」，确认关键词后才写进正式黑白名单。
本文说明 2026-09-12 改版后的操作方式。

## 页面结构

- 顶部「手动投递」：粘贴路径、选择白/黑名单、按状态和关键字筛选。
- 下方 Tab：`白名单待审` / `黑名单待审`，各自一张占满整行的表格，数字是当前列表条数。
- 每行分两部分：上半行是候选词、确认关键词输入框、状态和单条操作；下半行常驻显示完整路径。

## 确认关键词的四种方式

1. **点候选词**：点一下填进输入框。`Shift+点击` 是追加而不是替换，可以把两个候选拼成一个词。
2. **在路径上划词**：在下半行的路径上拖选一段，松手就填进输入框；双击选词同样生效。填入时自动去掉首尾空白和标点。
3. **编辑弹层**：点输入框右侧的笔形按钮，弹层里是完整路径，删掉不需要的部分后确认。
4. **直接在输入框里打字**。

任何一种方式填进关键词，这一行都会自动勾选并高亮；清空输入框会自动取消勾选。

## 批量操作

选中任意一行后，页面底部浮出操作栏，显示 `已选 N 条 · 其中 M 条已填关键词`。

| 按钮 | 作用 | 说明 |
| --- | --- | --- |
| 批量批准 | 把已填关键词的行写进当前 Tab 对应的名单 | 先弹确认并列出即将写入的词；没填关键词的选中行会被跳过 |
| 批量忽略 | 标记为已忽略，不写名单 | 可以再恢复为待审核 |
| 批量加入忽略库 | 把选中行里的候选词加入忽略库 | 弹层里逐个勾选要忽略的词，以后不再作为候选出现 |
| 批量删除 | 从待审核列表抹掉记录 | 不可恢复，强制确认 |

批量操作只作用在当前 Tab 上，不会影响另一个名单。

## 结果反馈

批量提交是**逐条独立处理**的，一条失败不影响其它条：

- 成功的行直接从列表消失，只刷新顶部统计数字，列表不会整页重拉，滚动位置不跳。
- 失败的行留在原地、整行标红，路径下方直接写出失败原因（例如「关键词已存在于 blacklist，不能直接归入 whitelist」）。
- 顶部提示汇总 `批准成功 10 条，失败 2 条`。

## 相关接口

| 接口 | 说明 |
| --- | --- |
| `POST /review-intake/items/batch-approve` | 入参 `{"items": [{"id": 1, "keyword": "词"}], "note": null}` |
| `POST /review-intake/items/batch-dismiss` | 入参 `{"ids": [1, 2]}` |
| `POST /review-intake/items/batch-delete` | 入参 `{"ids": [1, 2]}` |

三个接口统一返回 `{"succeeded": n, "failed": m, "results": [{"id", "ok", "item", "error"}]}`。
单条的 `approve` / `dismiss` / `restore` / `delete` 接口保持不变，快捷键投递流程不受影响。
