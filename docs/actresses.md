# 女优档案与联动删片

18x 按 115 番号片（`302porn_tv1`）NFO 里的演员建「女优档案」，每个人是黑名单、白名单或未标之一：

- **黑名单用来删片**：拉黑一个人后，她的片子进入「待删清单」。只有在网页上勾选并确认的片子才会删除，删除时连同 115 原文件、`porn_tv1` 的 STRM 和 `302porn_tv1` 的番号目录一起删掉，Jellyfin 里的条目随后消失。
- **白名单用来保护和归类**：片子里只要有受保护的人就不删；白名单女优在 Jellyfin 里有自己的合集。

页面在左侧导航「流程」组里：「女优」（`/actresses`）和「女优删除」（`/actress-deletes`）。

设计见 `docs/superpowers/specs/2026-11-25-actress-archive-design.md`，实施计划见 `docs/superpowers/plans/2026-11-25-actress-archive.md`。

## 工作方式

- **演员从哪来**：只看番号目录里 NFO 的 `<actor><name>`。一部片 = `302porn_tv1/<演员>/<番号>` 这个番号目录；分段片（CD1 / CD2）同属一部，演员取全部分段的合集。NFO 缺失或解析失败的片子没有演员，不会进待删清单。演员目录名不参与判断。
- **名字怎么比**：先全角转半角、去掉标点，再去掉全部空格，所以「甲 乙」和「甲乙」算同一个人。规范名和别名都参与比对，别名在全部女优之间唯一。
- **女优名只写女优自己的表**，不进关键词库，所以不影响 DEL 脚本、sehuatang 过滤、下载过滤和本地整理。关键词白名单只读不写。
- **建档**：每日任务把 NFO 里出现、但还对不上任何档案的名字自动建档为「未标」，并重算每个人的片数。播放器按片查演员时，对不上的名字也会当场建档。
- **合并**：同一个人在不同片里写法不同时，在女优详情里「合并到另一位」：她的名字和别名变成对方的别名，标记记录转过去，她本人的档案删除。一黑一白不能合并，要先改状态。

### 什么片子会进待删清单

一部片同时满足以下四条才算应删：

1. 演员里至少有一个人是黑名单；
2. 演员里没有任何人受保护。**受保护**指：档案里是白名单；或者演员名（演员能对上档案时，也比她的规范名和所有别名）命中启用中的关键词白名单（`whitelist`）或 Emby 白名单（`emby_whitelist`）的规范名或别名。同一个人既在档案黑名单、又命中关键词白名单时，按受保护算；
3. 没有被标为「保留」；
4. 片子在最近一次扫描中仍然有效。

待删清单是一份持续更新的名单：改状态、加删别名、合并、撤销保留、每日任务都会按上面的规则重算一遍，新应删的片子加进来（默认勾选），不再应删的自动移出。每日任务加进来的新片不发通知，下次打开页面时看到。

## 配置

只写变量名和示例路径，实际值放生产 `.env`。

| 变量 | 默认 | 说明 |
|---|---|---|
| `ACTRESS_ENABLED` | `false` | 女优功能总开关。还需要 `JELLYFIN_ENABLED=true`（演员名来自 Jellyfin 扫描）。 |
| `ACTRESS_SOURCE_ROOT` | 空 | `porn_tv1` 的**可写**根目录，删 STRM 只能落在这里面。生产示例：`/mnt/cache/docker1/alist-strm/video/porn_tv1` |
| `ACTRESS_ORGANIZED_ROOT` | 空 | `302porn_tv1` 的**可写**根目录，删番号目录只能落在这里面。生产示例：`/mnt/cache/docker1/alist-strm/video/302porn_tv1` |
| `ACTRESS_PATH_MAP` | 空 | 扫描路径（只读挂载）换成可写路径，写成 `旧前缀=>新前缀`，多条用逗号分隔；按最长前缀、只在目录边界匹配。生产示例：`/mnt/user/docker1/alist-strm/video=>/mnt/cache/docker1/alist-strm/video` |

还依赖这些已有配置：

- `MEDIA_LIBRARY_STRM_ROOTS`：115 番号库的扫描根目录。**没配置时**，刷新档案、重算待删清单、白名单合集同步、改状态、加删别名、合并、撤销保留、检查 115、建删除批次一律拒绝执行，不改任何数据（否则一部片都读不到，会把片数清零、把清单清空）。女优功能开着时，这还会让当天的合集同步任务记为失败（关键词合集在它之前已同步完）。
- `JELLYFIN_BASE_URL` / `JELLYFIN_API_KEY`：两项都要配。没配齐时，18x 启动时不开每日任务循环，整条每日链（扫描、女优刷新、合集同步）都不跑；头像一律显示占位；删除批次之后不扫库，记为「未扫库」。女优刷新仍可用接口手动触发（只要求 `JELLYFIN_ENABLED=true`）。
- 115 沿用现有客户端和令牌。

开关的效果：

- `ACTRESS_ENABLED` 关闭时：每日任务不跑女优步骤、不建待删清单、不同步女优合集。会改数据或起任务的接口返回 409，包括按片查演员（它会当场建档）、改状态、刷新、勾选、保留、检查 115、撤销保留、建删除批次、续跑、加删别名、合并。只读接口照常：女优列表、详情、待删清单、保留名单、历史批次和批次详情。
- 两个可写根目录没有都配齐时：建删除批次和续跑返回 409「女优删除未就绪」，其余功能照常。
- `ACTRESS_PATH_MAP` 写法不对时：「检查 115」返回 409；执行删除时批次标为「中断」，一部片都不动。

## 每日任务链里的位置

每天 `JELLYFIN_DAILY_RUN_HOUR`（默认 3 点）按顺序跑（前提是 Jellyfin 地址和 API Key 都已配置，见上文）：

1. **扫描**（`jellyfin:scan`）：扫两类媒体，同时把每个 115 STRM 条目的 NFO 演员名单存下来（每次整体重算，不留历史）。
2. **女优刷新**（`actress:refresh`，只在功能开启时）：新名字建档、重算片数，再按规则重算待删清单。这一步失败只记在它自己的任务上，不挡后面的合集同步。
3. **合集同步**：先同步关键词合集，功能开启时接着同步白名单女优合集（女优合集的成员要用关键词同步写入的 Jellyfin 条目 ID，所以排在后面）。
4. **显示名同步**（开关默认关闭）。

女优刷新也可以手动触发：`POST /api/actresses/refresh`（与每日任务的女优步骤相同；同一时间只跑一个）。

### 白名单合集

- 每个白名单女优一个 Jellyfin 合集，名字用规范名，带 `18x-managed` 标签，成员是她出演的、已在 Jellyfin 找到条目的有效片子。还没有可放的片子时不建空合集。
- 增量增删成员，只动 18x 自己建的合集，单个合集失败不影响其他。
- 移出白名单或被合并删除后，她的合集先清空再删除（只限 18x 建的）。
- 和关键词合集或手工合集同名时标为冲突，两边都不改，只在同步结果里计数。

## 页面操作

### 女优（`/actresses`）

- 顶部显示黑名单、白名单、未标的人数；可以按名字或别名搜索、按状态筛选、按片数或名字排序。
- 每行可以「拉黑」「加白」「设为未标」，也可以勾选多人批量改。改完立刻重算待删清单，提示新加入和移出了几部。
- 点一行打开详情：头像（由 18x 向 Jellyfin 转取，取不到显示占位）、别名增删、合并到另一位、标记记录（来源：网页 / 播放器 / 导入 / 合并）、她的片子和同片演员的状态。

### 女优删除（`/actress-deletes`）

三个标签：

- **待删清单**：每部片显示番号、标题、因为谁（黑名单的人）、同片其他演员和状态、115 文件状态（未检查 / 可解析 / 已不存在 / 有问题）。
  - 勾选 = 本次删除；不勾选 = 这次不删，留在清单里下次再看。有全选、全不选。
  - 「保留」：移出清单并记入保留名单，以后重算不再提出它。
  - 「检查 115」：只读查看勾选的片子在 115 上还能不能找到，一次最多 50 部（页面自动分批），不删任何文件。
  - 「确认删除」：确认框里的 N 部就是这一刻页面上勾选的片子，**只删这一份**（请求里带这些番号目录，服务端不再按自己存的勾选去删）。这期间清单有变化（有片子已不在清单里、确认框打开时清单重拉过或勾选变了），会提示「清单有变化，请刷新后再确认」或「清单有变化，请重新确认」，**一部都不删**。勾选写库、清单重拉、检查 115、保留任一在进行时，勾选框和这几个按钮都不能点。
- **历史批次**：每个删除批次的状态、已删 / 失败 / 跳过部数、Jellyfin 扫库结果；「查看」看逐部片、逐文件的结果；失败或中断的批次有「重试失败的」按钮。
- **保留名单**：可以撤销保留；撤销后仍应删的片子回到待删清单。

## 删一部片的顺序

确认后建一个删除批次，交给后台任务（`actress:delete`，同一时间只跑一个）逐部片执行，不并发。开始前先确认两个可写根目录都在、并建一次 `porn_tv1` 的「STRM 地址 → 路径」索引；做不到就把整个批次标为失败，一部片都不动，也不调 115。

每部片按以下顺序做，**任何一步失败就停在这部片**（后面的步骤不做），记失败原因，继续下一部：

1. **再判断一次规则**：已不在扫描结果里、已受保护、已标保留、没有黑名单演员的，记为跳过并写原因。
2. **核对本地**：用 `ACTRESS_PATH_MAP` 把番号目录换成可写路径，必须真实存在、恰好在 `302porn_tv1` 可写根下两层（`<根>/<演员>/<番号>`）、路径上不经过链接；每个分段 STRM 也必须就在这个番号目录里。不合格说明路径换算不对，这部片**一个 115 文件都不删**。
3. **解析 115 文件**：读每个 STRM 里的 OpenList 地址，解出 115 路径，按路径查 file_id，必须确认是文件。先把全部分段解析完，有一个解析失败就一个都不删。
   - 115 报错里含中文「不存在」才算「115 已不存在」，视为这一步成功；收紧 `MISSING_MARKERS` 之前，含「不存在」的鉴权类报错可能被误判为已不存在（见上线检查清单第 3 条）。其他报错（包括英文 not found）一律当失败，本地文件不删。
4. **删 115 原文件**：逐个删除，每删成功一个立刻落库。
5. **删 `porn_tv1` 里地址相同的 STRM**（按 STRM 内容找，不依赖硬链接）。
6. **删 `302porn_tv1` 的番号目录**（整个目录）。演员目录如果因此变空，只删这个空目录，不往上递归；空目录删不掉不影响这部片的结果。
7. 在 18x 里把这部片的扫描条目标为失效，并移出待删清单。

本地删除只会落在两个可写根目录里：`porn_tv1` 下只删 `.strm` 普通文件，`302porn_tv1` 下只删恰好两层深的番号目录和变空的演员目录，路径上任何一段是链接都拒绝。不会调用 Jellyfin 的「删除条目」接口，也不做全量刷新。

整个批次删掉了至少一部片时，再让 Jellyfin 对 115 番号库做一次普通扫描（「扫描新增和更新的文件」，不替换元数据和图片），结果记在批次上：已触发扫库 / 未扫库 / 扫库失败。扫库失败不影响删除结果，可以在 Jellyfin 里手动对该库做一次普通扫描。

### 失败时会怎样

- **115 删除失败**：这部片的本地 STRM 和番号目录都还在，记为失败，可以重试。
- **本地删除失败**（115 已删）：记为失败；重试时已删 / 已不存在的 115 文件不会再删一次，接着做本地这几步。
- **整个执行因意外异常被打断**：批次标为「中断」，已经做完的片子和文件都有记录。

### 怎么续跑

在「历史批次」里，状态为「失败」或「中断」的批次有「重试失败的」按钮（接口 `POST /api/actresses/delete-batches/{批次 ID}/resume`）。续跑只处理待执行和失败的片子；每部片照样先重新判断规则、核对本地；已删和已不存在的文件行不再重做，同一个 115 文件不会删两次。删除任务在跑时不能续跑，也不能建新批次。

## 给播放器（fklema）用的接口

沿用 18x 现有登录：

- `GET /api/actresses/by-media?jellyfin_item_id=…` 或 `?path=…`（STRM 路径或番号目录，二选一）：返回番号、`media_item_id`、是否在待删清单里、按 NFO 顺序的演员和各自状态。对不上档案的演员当场建档为未标。
- `POST /api/actresses/status`：`{"actress_ids": [...], "status": "blacklist|whitelist|none", "source": "player", "media_item_id": …}`。`media_item_id` 回传 by-media 返回的那个值，标记记录里会记下是从哪部片上标的。返回状态有变化的人数和待删清单的增减部数。
- 功能关闭时这两个接口都返回 409。

## 旧 Emby 黑白名单导入

`scripts/actress_import_emby_lists.py` 一次性把启用中的 `emby_blacklist` / `emby_whitelist` 关键词按人名设成女优状态（标记来源记为「导入」），关键词本身不改不删。

```bash
# 只列出，不写入（也不建档）
docker exec docker-app-1 python scripts/actress_import_emby_lists.py
# 确认无误后写入，写入后重算待删清单
docker exec docker-app-1 python scripts/actress_import_emby_lists.py --apply
```

- 每条关键词输出一行，标明「将设置 / 已设置 / 不变 / 冲突」，之后是一行汇总（共几条、各几条）。只列出时最后还有一行「只列出，未写入」的提示，汇总在它上一行。
- 同一人同时在 Emby 黑名单和白名单里的不导入，列为冲突。
- 档案里已是相反状态的人不覆盖，列为冲突（备注「档案里已是白名单 / 黑名单」）；已是目标状态的记为不变。只改档案里未标的人。
- `--apply` 要求女优功能已开启、`MEDIA_LIBRARY_STRM_ROOTS` 已配置，否则不写入并返回非 0。

## 上线检查清单

每一步都要用户批准后再做（设计文档第八节）。

1. **只读统计生产数据**：演员总数、每人片数分布、多人片比例、NFO 缺失比例、旧 `emby_blacklist` / `emby_whitelist` 条数。
2. **核实路径换算**：同一文件在 `/mnt/user/docker1/alist-strm/video/...` 和 `/mnt/cache/docker1/alist-strm/video/...` 下 inode 一致，才能用 `ACTRESS_PATH_MAP`；不一致要调整 18x 容器挂载（需用户批准）。
3. **核实 115「已不存在」的报错**：`app/services/actresses/remote_115.py` 的 `MISSING_MARKERS` 目前只认「不存在」三个字。只读核实真实 115 对不存在路径的报错文本或错误码，收紧成那条报错的完整文字或错误码（不能只匹配裸「不存在」，鉴权类报错也可能含这几个字）。没核实前，115 上已删的片子会判失败、本地不删（安全方向）。
4. **核实 115 按路径查询的返回**：真实 115 `fs_info` 按路径查询是否返回 `data.file_id` 和 `file_category`（`"1"` 是文件）；不返回的话所有片子都会判失败（安全方向）。
5. **核实 115 删除是否进回收站**：不进的话删除不可找回，网页确认框里「115 文件进回收站」这句要改，女优删除页顶部说明（`ActressDeletePage.tsx` 里「115 原文件进回收站」）也要跟着改。
6. **核实 Jellyfin**：`/Persons/{名字}` 不带 userId 能否取到人物头像；`POST /Items/{库 ID}/Refresh`（Default 模式）是否只做普通扫描。
7. **迁移**：只在 SQLite 上验证过。部署前备份 organizer 库，部署后确认 alembic 升到 `20261126_0019`。然后配置四个 `ACTRESS_*` 项，打开 `ACTRESS_ENABLED`。
8. **首次真实删除只勾 1 部用户指定的片子**：按设计文档验收标准第 5 条核对（115 原文件消失并能在回收站看到、`porn_tv1` STRM 和 `302porn_tv1` 番号目录消失、Jellyfin 扫库后条目消失、其他目录没有变化、没勾选的片子仍在清单里），并观察一天，确认没有「删了又回来」（OpenList 缓存 / alist-strm 重新生成 STRM）。
9. **旧 Emby 名单导入放在首删之后**：先不加 `--apply` 看列表，再加 `--apply`。档案里已有相反状态的人记为冲突、不覆盖。
10. **播放器（第三段 fklema）**：功能关闭时写接口返回 409；改状态时回传 by-media 返回的 `media_item_id`。

## 回退

- 只想停用：把 `ACTRESS_ENABLED` 改回 `false` 并重建 18x 容器让配置生效，不动代码和库。每日任务不再跑女优步骤，删除接口返回 409；档案、清单和批次记录留在库里。
- 要回退代码：容器启动时会先执行 `alembic upgrade head`，失败就起不来，所以库还在 `20261126_0019` 时不能直接换回旧代码。必须先在新代码上把迁移降到 `20261125_0018`（会删掉女优相关的全部表和数据，先备份），再把代码回退到 `a0977f3b` 重建。
- 已删的 115 文件只能从 115 回收站找回（前提是删除进了回收站）；本地 STRM 和番号目录由 alist-strm 和 MDC 按 115 目录重新生成。
