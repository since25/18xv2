# Jellyfin 第一版 Implementation Plan

> **For agentic workers:** 本计划按用户指定方式执行：后端任务由 Codex（`codex exec`）实施，Claude 写任务书并验收；前端任务由 Claude 实施。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 18x_v2 扫描本地「已整理」和 `302porn_tv1` 的媒体，按白名单关键词精确匹配，并通过 Jellyfin API 按关键词维护合集；附带 Jellyfin + 第二个 MediaWarp 的部署文件。

**Architecture:** 新增 `app/services/jellyfin/` 模块：纯函数 matcher → 扫描服务（落库 `jellyfin_media_items` / `jellyfin_media_keywords`）→ Jellyfin HTTP 客户端 → 合集同步服务（`jellyfin_keyword_collections`）。手动触发和每日定时都经 `BackgroundJobService` 建任务。前端新增「Jellyfin」页面。

**Tech Stack:** FastAPI、SQLAlchemy 2、Alembic、PostgreSQL（测试用 SQLite）、httpx、pytest；React + TypeScript + Vite + Vitest。

**Spec:** `docs/superpowers/specs/2026-11-01-jellyfin-v1-design.md`（第 5.6 节为后端细化，冲突时以 5.6 为准）

## Global Constraints

- 代码注释、docstring 使用中文；沿用现有风格，不重构、不格式化无关代码。
- 18x 和 Jellyfin 不向任何媒体目录写文件；扫描只读目录元信息和 `.nfo` 文本，不读视频内容、不算哈希。
- 匹配只用 `keyword_type == "whitelist"` 且 `status == "active"` 的关键词（规范名 + 别名），精确匹配；不用 `local_organize` 的模糊子串。
- 本地目录名先按原始字符串 `"__"` 拆段，再逐段 `normalize_keyword_text`（`app/services/keywords/registry_service.py:22`）。
- 115 侧只收 `.strm`；本地只收视频扩展名：`.mp4 .mkv .avi .mov .wmv .flv .ts .m2ts .webm .m4v .mpg .mpeg .rmvb .iso`。
- 未启用（`JELLYFIN_ENABLED` 为 false，或缺 `JELLYFIN_BASE_URL` / `JELLYFIN_API_KEY`）时：不建客户端、不发请求、不起定时循环；同步接口返回 409。扫描不依赖 Jellyfin，只要 `JELLYFIN_ENABLED=true` 即可运行。
- 只改动带 `18x-managed` 标签且在 `jellyfin_keyword_collections` 中有记录的合集。
- 密钥只从环境变量读；代码、测试夹具、文档中不出现真实密钥、真实人名或真实关键词（测试用"演员甲""关键词乙"之类）。
- 后端测试命令：`.venv/bin/python -m pytest tests/jellyfin -q`；全量回归用 `scripts/remote-test.sh backend`（Claude 执行）。
- 不 git commit / push；提交由用户决定。

## Review Focus

1. **根目录挂载丢失**：配置的根目录不存在、不可读或为空 → 扫描任务失败，已有条目一个都不标失效。（Task 2 测试 `test_scan_missing_root_fails_without_deactivating`）
2. **Jellyfin 还没扫完**：路径在 Jellyfin 中找不到 → 条目保持 pending，合集不移除任何成员。（Task 3 测试 `test_sync_keeps_pending_and_never_removes_when_unresolved`）
3. **同名手工合集**：Jellyfin 已有同名但无 `18x-managed` 标签的合集 → 标 conflict，不改它。（Task 3 测试 `test_sync_marks_conflict_for_unmanaged_same_name`）
4. **组合目录与下划线**：`甲__乙` 拆成两个关键词；单下划线 `甲_乙` 不拆，整体归一化后匹配。（Task 1 测试 `test_split_double_underscore_only`）
5. **关键词被合并删除**：关键词行删除后，其合集记录变 retired，下次同步删除这个带标签的合集。（Task 3 测试 `test_sync_deletes_retired_managed_collection`）

### Task 2: 媒体扫描服务（后端，Codex：astra / xhigh）

**Files:**
- Create: `app/services/jellyfin/scan_service.py`
- Test: `tests/jellyfin/test_scan_service.py`

**Interfaces:**
- Consumes: Task 1 的模型、`build_keyword_index`、`match_local_folder`、`match_strm_item`；`parse_nfo_actors(xml_text) -> list[ParsedActor]`（`app/services/emby_media_actions/nfo_parser.py:14`，取 `.name`；抛异常即视为 NFO 错误）。
- Produces: `class MediaScanError(Exception)`；`MediaScanService.scan(db: Session, *, local_roots: list[str], strm_roots: list[str], job_id: str | None = None, batch_size: int = 500) -> dict`，返回 `{"local_files": int, "strm_files": int, "matched": int, "unmatched": int, "nfo_error": int, "deactivated": int}`。

规则（spec 5.3 / 5.6）：
- 本地：根下每个**顶层目录**的名字做匹配，其下递归所有视频文件都归属这些关键词；根目录下直接放的文件按 unmatched 处理。
- STRM：每个 `.strm` 找同目录同名 `.nfo`（`<stem>.nfo`），没有则 `actor_names=None` 但 match_state 记为 `unmatched` 或 `matched`（缺 NFO 不算错误，只有解析异常才是 `nfo_error`）；目录名取根下第一级目录。
- upsert 按 `(source, path)`；每条记录写 size、mtime、last_seen_at、last_seen_job_id、active=True；每条记录的关键词关联整体替换为本次结果。
- 每 `batch_size` 条 commit 一次。全部根扫完后，才把 `last_seen_job_id != 本次` 且 `source` 属于本次已扫来源的条目设为 `active=False`（只针对本次配置的根路径前缀下的条目）。
- 任一配置根：不存在、不是目录、不可读、或一个媒体文件都没有 → 在任何失效标记前抛 `MediaScanError`（已提交的 upsert 批次可以保留）。
- 未生成 `job_id` 时内部生成一个 uuid 用作扫描代次。

### Task 3: Jellyfin 客户端与合集同步（后端，Codex：astra / xhigh）

**Files:**
- Create: `app/services/jellyfin/client.py`、`app/services/jellyfin/collection_sync_service.py`
- Test: `tests/jellyfin/test_client.py`、`tests/jellyfin/test_collection_sync.py`

**Interfaces:**
- Consumes: Task 1 模型与配置。
- Produces（`client.py`，写法参照 `app/services/downloader/client.py`，用 httpx，可作上下文管理器，构造参数允许注入 `transport` 便于测试）：
  - `class JellyfinError(Exception)`
  - `JellyfinClient(base_url: str, api_key: str, timeout: float, page_size: int, transport=None)`；请求头 `Authorization: MediaBrowser Token="<api_key>"`。
  - `iter_media_paths() -> Iterator[tuple[str, str]]`：分页 `GET /Items?Recursive=true&IsFolder=false&Fields=Path&StartIndex=&Limit=`，产出 `(path, item_id)`；任何一页失败抛 `JellyfinError`（调用方据此判定"列表不完整"）。
  - `list_collections() -> list[dict]`：`GET /Items?IncludeItemTypes=BoxSet&Recursive=true&Fields=Tags`，返回 `{"id","name","tags"}`。
  - `get_collection_item_ids(collection_id) -> set[str]`：`GET /Items?ParentId=<id>`（分页）。
  - `create_collection(name, item_ids: list[str]) -> str`：`POST /Collections?Name=&Ids=`，返回新 id。
  - `add_to_collection(collection_id, item_ids)` / `remove_from_collection(collection_id, item_ids)`：`POST` / `DELETE /Collections/{id}/Items?Ids=`，Ids 每批不超过 100 个。
  - `set_name_and_tags(collection_id, name: str, tags: list[str])`：先 `GET /Items/{id}`（带 `userId` 不需要时省略）取完整对象，改 `Name`、`Tags` 后 `POST /Items/{id}`。
  - `delete_item(collection_id)`：`DELETE /Items/{id}`。
  - 重试：连接错误、429、5xx 最多重试 3 次，退避 1s / 2s / 4s（测试中可注入 sleep 函数为空操作）；4xx（除 429）不重试，直接抛 `JellyfinError`。
- Produces（`collection_sync_service.py`）：`CollectionSyncService.sync(db: Session, client: JellyfinClient) -> dict`，返回 `{"collections_created","collections_renamed","collections_deleted","items_added","items_removed","pending_items","conflicts","errors"}`。
  - 常量 `MANAGED_TAG = "18x-managed"`。

同步算法（spec 5.4 / 5.6）：
1. 尝试 `iter_media_paths()` 建 `path → item_id` 索引；成功则 `listing_complete=True`，并回写 active 条目的 `jellyfin_item_id` 与 `resolve_state`（找到 → resolved，找不到 → pending）；失败则 `listing_complete=False`，沿用库里已有的 resolved item_id。
2. 应有成员：每个有 active 条目关联的关键词 → 其 resolved 的 item_id 集合。
3. 现有合集：`list_collections()`。对每个应有关键词：
   - 有 active 映射且 Jellyfin 中该 id 存在并带 `MANAGED_TAG` → 名字与当前规范名不同则改名；加缺的成员；`listing_complete` 时才移除多余成员。
   - 映射存在但合集已不存在 → 重新创建并更新映射。
   - 无映射：Jellyfin 已有同名合集且无标签 → 写一条 status=conflict 的映射（collection_id 为空），计入 conflicts，跳过；否则 `create_collection` + `set_name_and_tags`（加标签），写 active 映射。
   - 映射存在、合集存在但标签被手工去掉 → status=conflict，跳过。
4. retired：`keyword_entry_id` 为 None 的映射，或关键词已无任何 active 关联 / 已非 active 白名单 → 若合集存在且带标签则 `delete_item`，映射 status=retired、记录 retired_at；已 retired 的不重复处理。
5. 单个合集出错：记 `last_error`，计入 errors，继续下一个；不因错误触发任何移除或删除。

### Task 4: 接口、后台任务与每日定时（后端，Codex：sol / high）

**Files:**
- Create: `app/api/routes/jellyfin.py`、`app/schemas/jellyfin.py`、`app/services/jellyfin/job_runner.py`
- Modify: `app/main.py`（`include_router`；lifespan 中按开关启动/取消每日循环）
- Test: `tests/jellyfin/test_routes.py`、`tests/jellyfin/test_job_runner.py`

**Interfaces:**
- Consumes: `MediaScanService.scan`、`CollectionSyncService.sync`、`JellyfinClient`、`BackgroundJobService.create/update/list_active`（`app/services/background_job_service.py`）。
- Produces（`job_runner.py`）：
  - `JOB_SCAN = "jellyfin:scan"`、`JOB_SYNC = "jellyfin:sync"`
  - `jellyfin_scan_enabled(settings) -> bool`（= `jellyfin_enabled`）；`jellyfin_sync_enabled(settings) -> bool`（再要求 base_url 与 api_key）。
  - `class JobAlreadyRunning(Exception)`
  - `start_job(db, job_type: str) -> str`：同类型已有运行中任务（`list_active`）则抛 `JobAlreadyRunning`；配合模块级 `threading.Lock` 防止并发创建；返回 job_id。
  - `run_scan_job(job_id: str) -> None` / `run_sync_job(job_id: str) -> None`：自建 `SessionLocal`，执行服务，结果写入任务的结果字段，异常写失败信息（不抛出）。
  - `async def jellyfin_daily_loop(settings) -> None`：每分钟检查一次；本地时间到达 `jellyfin_daily_run_hour` 且当天未跑过 → 依次跑扫描、（同步已启用时）同步；`jellyfin_daily_run_hour == -1` 时不启动。
- Produces（路由，prefix `/jellyfin`，鉴权沿用全局中间件）：
  - `GET /jellyfin/status` → `{"scan_enabled": bool, "sync_enabled": bool, "local_roots": [...], "strm_roots": [...], "latest_scan": job|None, "latest_sync": job|None, "counts": {"active_items","matched","unmatched","nfo_error","pending_resolve"}, "collections": {"active","conflict","retired"}}`
  - `POST /jellyfin/scan` → 202 `{"job_id"}`；未启用 409；已有运行中 409。
  - `POST /jellyfin/sync` → 同上（sync 未启用 409）。
