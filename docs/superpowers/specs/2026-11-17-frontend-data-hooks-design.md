# 前端统一取数层 设计

日期：2026-11-17
状态：用户已确认方案，范围为“一次全做完”

## 意图

23 个页面里 22 个各自手写“加载中 / 出错提示 / 刷新”，全站约 150 处几乎相同的代码；登录中途过期没有统一处理；多数页面没有“后发请求先返回”的保护。目标是把这些收敛到一套取数工具，页面只写“取什么、取到后怎么显示”。

## 目标

- 提供两个工具：读取用的 `useApiQuery`，操作用的 `useApiAction`。
- 登录过期（接口返回 401）时统一回到登录页，重新登录后回到原页面。
- 22 个取数页面全部迁移到新工具（登录页不取数，不在范围内）。
- 前端规范检查（lint）、测试、构建全部通过。现有 2 个既有 lint 报错位于本轮要改的页面内，一并消除。

## 不做的事

- 不引入第三方取数库，不做请求缓存和跨页面数据共享。
- 不拆分大页面、不调整页面结构和样式（那是下一项）。
- 不改后端，不改接口地址和数据类型定义。
- 不改进度推送（SSE 订阅）和定时轮询的机制本身；这些代码保留在页面里，只把其中普通的“读取”和“操作”换成新工具。

## 不能出现的结果

- 任何页面的显示内容、提示文字、按钮行为、加载指示发生用户可感知的变化（下述“已知行为变化”除外）。
- 原来静默失败的请求变成弹出报错，或原来会报错的请求变成静默。
- 为了通过检查而加 `eslint-disable`，或为了通过测试而删除、放宽现有用例。

## 考虑过的做法

1. **自写轻量工具（采用）**。无新依赖；建在现有 `api/client.ts` 和各 `api/*.ts` 模块之上，现有测试的模拟方式可以继续用。
2. **引入成熟取数库**。主要价值是缓存和跨页面共享，单人工具用不上；所有页面测试都要加一层包装。不采用。
3. **只加登录过期处理**。改动最小，但 150 处重复原样保留。不采用。

用户已确认做法 1，并选择一次迁移全部页面（而不是分三批上线）。

## 设计

### useApiQuery（读取）

`frontend/src/hooks/useApiQuery.ts`

- 入参：取数函数、依赖列表、可选项（`enabled` 是否自动执行、`silent` 出错是否不弹提示、`initialData` 初始值）。
- 返回：`data`、`loading`、`error`、`reload()`、`setData()`。
- 行为：
  - 挂载时和依赖变化时自动执行；`enabled` 为假时不执行。
  - 只采用最后一次发出的请求的结果，更早的请求返回后丢弃；组件卸载后不再更新状态。
  - 出错时默认用 antd 的 `message.error` 显示错误信息；`silent` 时不显示。401 不显示（由全局处理）。
  - `reload()` 可手动刷新，返回 Promise；支持静默刷新（不切换 `loading`），供定时轮询使用。
  - 重新加载期间保留上一次的数据，不清空。

### useApiAction（操作）

`frontend/src/hooks/useApiAction.ts`

- 入参：执行函数、可选项（`successMessage` 成功提示，字符串或函数；`onSuccess` 成功回调；`silent`）。
- 返回：`run(...args)`、`loading`。
- 行为：`run` 永不抛异常，返回 `{ ok: true, data }` 或 `{ ok: false, error }`；出错时默认弹出错误信息（401 除外）；执行期间 `loading` 为真。

### 登录过期统一处理

- `api/client.ts`：收到 401 且请求不是 `/auth/login`、`/auth/me` 时，调用已注册的处理函数，然后照常抛出 `ApiError`。提供 `setUnauthorizedHandler(fn)`。
- `App.tsx`：已登录状态下注册处理函数——把登录状态置为未登录，提示“登录已过期，请重新登录”（短时间内多个请求同时 401 只提示一次），回到登录页并记住当前地址；重新登录后回到该地址。

### 迁移规则

- 普通的“页面打开时加载、筛选变化时重新加载”改用 `useApiQuery`；提交、删除等操作改用 `useApiAction`。
- 迁移后不再需要的 `setTimeout(0)` 首次加载写法、手写的 `loading` 状态和 `try/catch` 一并删除。
- 每个请求原来的出错表现必须保留：原来弹错误的仍弹同样的文字，原来静默的用 `silent`。
- 进度推送订阅、轮询定时器、需要按顺序串联多个请求且中途有分支提示的复杂流程，可以保留原写法；在汇报里逐个列出并说明原因。

## 已知行为变化

1. 登录过期后自动回到登录页并提示，不再在各页面弹英文报错。
2. 快速切换筛选或翻页时，只显示最后一次请求的结果（原来可能短暂显示旧结果）。

## 测试

- 两个工具各自的单元测试：自动执行、依赖变化重取、竞态丢弃旧结果、卸载后不更新、出错提示与静默、401 不提示、手动与静默刷新、`run` 的成功与失败返回。
- 登录过期处理的测试：401 触发处理函数；`/auth/login`、`/auth/me` 的 401 不触发；多个 401 只提示一次；重新登录后回到原地址。
- 现有 21 个测试文件保持通过；不删除、不放宽现有用例。
- 验收：Spark 上 `scripts/remote-test.sh frontend` 退出码 0（测试、构建、lint 全过）。
