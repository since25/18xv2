# 115 番号库 NFO 重新翻译脚本 设计说明

> 日期：2026-11-27
> 状态：已过构建者审读，待用户确认
> 范围：18x `scripts/` 下新增一个命令行脚本，在生产容器里运行；不改 18x 网页、接口和数据库结构。

## 一、为什么做

115 番号库（`302porn_tv1`，Jellyfin「115番号」库）的标题和简介由 MDC 刮削时调用翻译接口生成。2 月首刮用的是 Google 翻译，6 月重刮换成了一个本地模型，质量都一般：人名乱翻、栏目名被硬翻、促销语没删干净，还有残留日文。用户已经接上了更好的模型（`qwen38`，OpenAI 兼容接口）。

想全库重翻，MDC 只有一条路：「重试」。重试会把每部片的所有站点重新刮一遍，再顺带翻译，全库要跑十几个小时，还会冒被站点封的风险，并且可能顺带改掉演员、标签等其他字段。翻译真正需要的日文原文，其实已经在 NFO 里了。

所以改成自己写脚本：从 NFO 里取原文，加上演员、番号、片商等参考信息交给模型，并发翻译，只把译文写回 NFO。这样做还有一个 MDC 做不到的好处：可以把这部片的演员名单和库里的中文写法一起告诉模型，让标题里的人名和 Jellyfin 里的演员名一致。

## 二、目标、不做的、绝不能发生的

**目标**

1. 对选定范围内的 NFO，从日文原标题、原简介重新翻译，写回标题和简介。
2. 先出「旧译 vs 新译」对比报告，用户看过后再写入；写入的必须是用户看过的那一份译文，不能再调一次模型。
3. 写入前备份，出问题能一条命令还原。
4. 写入后让 Jellyfin 对改过的条目强制重读 NFO，界面上马上能看到新译文。
5. 能按范围、数量抽样运行，方便先试 10～20 条。

**不做**

- 标题或简介本来就取自中文站（airav、sehuatang、麻豆等）的条目，那个字段不动。用户已确认：这部分原文只在 MDC 数据库里，不值得为它再取一遍源数据。
- 不重新访问任何刮削站点，不调用 MDC 的接口，不改 MDC 的配置和数据库。
- 不处理本地「已整理」库，也不处理 115 侧没有 NFO 的片子。
- 不做网页、按钮和定时任务。以后要常用，再包装成脚本中心的任务。

**绝不能发生（发生了就算失败，哪怕脚本跑完了）**

- 写出半截或格式坏掉的 NFO，导致 Jellyfin 读不出这部片。
- 改动标题和简介以外的任何标签，或者改了文件名、目录名。
- 改坏 NFO 的属主和权限，导致 MDC 以后写不了这个文件（NFO 属主是 `nobody:users`，权限 `666`，18x 容器是以 root 身份运行的）。
- 把模型输出的垃圾写进去，比如空文本、「标题：」这类前缀、整段还是日文、模型的拒绝话术。
- 翻译接口的密钥出现在日志、报告或文档里。

## 三、约束

- **运行位置**：生产容器 `docker-app-1`，命令形如 `docker exec docker-app-1 python scripts/nfo_retranslate.py ...`。脚本写法照现有的 `scripts/actress_clean_leftovers.py`：argparse，默认只预览，加参数才真正写入。
- **读写路径**：容器里 `302porn_tv1` 有两个挂载。`/mnt/user/docker1/alist-strm/video/302porn_tv1` 是只读的，也是 Jellyfin 和 18x 扫描记录里的路径；`/mnt/cache/docker1/alist-strm/video/302porn_tv1` 是可写的，女优删片（`ACTRESS_ORGANIZED_ROOT`）用的就是它。两者是同一批文件（已核对，NFO 数量一致）。写入走可写路径，去 Jellyfin 查条目时换成只读路径。不改 docker-compose。
- **范围判断的数据来源**：NFO 只在简介末尾有「由 xx 提供翻译」的标记，标题来自哪个站没有记录。每个字段的来源要读 MDC 数据库里的 `task.metadata_provider_info`（`Title`、`Outline` 两个键）。MDC 数据目录已经只读挂在 18x 容器的 `/app/mdc`，数据库是 `/app/mdc/mdc_ng.db`，开着 WAL。只读挂载下直接打开可能读不了，**要先把 `mdc_ng.db` 和 `-wal` 复制到临时目录再读**。
- **NFO 和 MDC 任务的对应**：`task.target_path` 形如 `/302video/302porn_tv1/<演员>/<番号>/<文件名>.strm`，把 `/302video/302porn_tv1` 换成 302porn_tv1 根目录，再把扩展名改成 `.nfo`，就是这个任务写的 NFO。多段视频的分段子任务（`primary_task_id` 不为空）没有自己的元数据，字段来源按主任务算。
- **演员对照表**：`/app/mdc/mapping_actor.xml`，每条形如 `<a zh_cn="麻仓忧" zh_tw="麻倉憂" jp="麻倉憂" keyword=",麻倉憂,松山真琴,…,"/>`。NFO 里的演员名已经是 MDC 换好的 `zh_cn` 写法。
- **翻译接口**：OpenAI 兼容的 `/v1/chat/completions`，地址、密钥、模型名放生产 `.env`。密钥只能由用户自己填，或者经用户同意后从 MDC 配置里复制过去；不写进代码和文档。
- **测试**：pytest 在 Spark 上跑，用 `scripts/remote-test.sh backend`，不在本机跑。
- **MDC 的 NFO 格式**（以生产配置为准）：
  - `<title>`、`<originaltitle>`、`<sorttitle>`、`<outline>`、`<plot>` 用 CDATA 包裹；`<originalplot>` 不用 CDATA，是转义后的文本。
  - `<title>` = `番号 + 空格 + 标题`；多段视频在末尾再加 ` cdN`（配置 `add_part_to_title`）。
  - `<originaltitle>` = `番号 + 空格 + 日文标题`，末尾常带演员名，例如 `MIAA-759 婚約したばかりの… 森沢かな`。
  - `<sorttitle>` 和 `<originaltitle>` 相同，是日文。
  - `<plot>` = 简介正文，加上 `<br>  <br>由 OpenAI 提供翻译` 这样的结尾（配置 `add_translated_by`）；`<outline>` 和 `<plot>` 内容相同。
  - `<originalplot>` 是日文原简介（机器翻译的条目才是日文；中文站来源的条目这里存的是那段中文）。
- **已知副作用，用户已接受**：脚本只改 NFO，MDC 数据库里还是旧译文。以后某条在 MDC 里被「重试」，会被 MDC 重新刮、重新翻译后覆盖。

## 四、方案比较

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A 脚本直接读写 NFO（已选）** | 18x 脚本读 NFO，调用模型，只替换标题和简介两个标签，备份后写回，再让 Jellyfin 刷新 | 不依赖 MDC，能并发，能带参考信息，改动范围最小；代价是 MDC 数据库和 NFO 的译文不一致 |
| B 翻译后经 MDC 编辑接口写回 | 调 `PUT /api/tasks/{id}/nfo`，让 MDC 自己写 NFO | 能保持 MDC 数据库同步；但 18x 容器连不到 MDC 后端（不同 Docker 网络、端口没对外开），多段视频每段都要单独提交，接口是闭源程序里没有公开说明的接口，MDC 升级后可能失效 |
| C 18x 脚本中心后台任务 + 网页 | 数据库表、接口、页面一整套 | 工作量是 A 的数倍；当前是一次性清理，不值得 |

用户选 A。

## 五、设计

### 5.1 两个阶段，两个命令

```
# 阶段一：翻译并出报告，不碰 NFO
python scripts/nfo_retranslate.py translate [--limit N] [--sample N] [--fields title,plot]
        [--path-prefix 演员目录/…] [--engine Google|OpenAI|…] [--workers 8]

# 阶段二：把某次翻译的结果写回 NFO，并刷新 Jellyfin
python scripts/nfo_retranslate.py apply --run <运行编号> [--skip 文件] [--no-refresh]

# 还原：用某次写入时的备份还原 NFO，并刷新 Jellyfin
python scripts/nfo_retranslate.py restore --run <运行编号>
```

- 每次 `translate` 生成一个运行编号（时间戳），对应目录 `data/nfo_retranslate/<运行编号>/`。`data/` 已挂到宿主机，容器重建后不会丢。
- `apply` 只写这次运行里通过检查的译文，不再调用模型。用户在报告里看到的就是最终写进去的。
- `--sample N` 随机抽 N 部，用于试跑；`--limit N` 取前 N 部，用于分批。
- `translate` 中途断了，再跑一次同样的命令加 `--resume <运行编号>`，跳过已翻译的片子。

### 5.2 范围怎么判断

以「一部片」为单位：同一个目录、同一个番号的 NFO 算一部片。多段的 cd1～cdN，以及同一番号的不同版本（例如 `-C` 字幕版和普通版），都放进同一组，**只翻译一次，写回组内每个 NFO**。

对每部片的每个字段（标题、简介）分别判断，三条同时满足才翻译：

1. 字段来源不是中文站。中文站名单：`airav_io`、`sehuatang`、`Madou`、`Madouqu`、`xiao_huang_shu`。来源取 MDC 主任务的 `metadata_provider_info`。
2. 对应原文（标题看 `<originaltitle>`，简介看 `<originalplot>`）含有日文假名。没有假名的说明原文本身就不是日文，跳过。
3. 原文去掉番号前缀后不为空。

**前提：先清旧版残留。** 2026-11-27 摸底发现，302porn_tv1 里有 668 个 STRM 不属于任何当前 MDC 任务（2 月首刮的旧命名、旧目录）。其中 606 个与新版是同一个文件；已批准的修复批次会把它们移到隔离区，剩下 62 个唯一副本保留。脚本要在这一步之后再跑。为了防止漏清，`translate` 会统计「找不到对应 MDC 任务的 NFO」：超过 100 个就提示「旧版残留可能还没清」并退出，加 `--force` 才继续。

NFO 找不到对应的 MDC 任务时（清理后只剩约 62 个唯一副本）：简介末尾带「由 xx 提供翻译」标记的，简介算在范围内；标题跳过。

**同一组里各个 NFO 的字段来源不一致时**，逐个 NFO 判断：译文以组内第一个「这个字段在范围内」的 NFO 为准翻译一次；写回时，只写那些自身这个字段也在范围内的 NFO。中文站来源的字段一律不写。（我的决定）

**硬链接数大于 1 的 NFO 跳过不写**，记录原因。原子替换会拆开硬链接。正常情况下 NFO 不是硬链接，这条只是保护。（我的决定）

**`--engine Google` 这类筛选**，按简介末尾的翻译标记挑片子。挑中的片子，标题、简介两个字段再各自按上面的规则判断。用途是先处理质量最差的 Google 旧译。

**跨运行的「已写入」记录。** 每次 `apply` 成功写入后，把「NFO 路径、字段、模型名、写入后的文件哈希」追加到 `data/nfo_retranslate/applied.jsonl`。之后再跑 `translate` 时，如果某个 NFO 的当前哈希和记录里写入后的哈希一致，说明它从上次写入后没被改过，这个文件里已写过的字段就跳过。这样「先跑 Google，再跑剩下的」时，第二次不加 `--engine` 直接跑，不会把已经确认写入的再翻一遍。要强制重翻，加 `--redo`。（我的决定）

当前数据的规模（2026-11-27 只读统计）：约 1400 部片的标题、1600 部的简介在范围内。

### 5.3 给模型的内容

每部片的标题、简介**分开请求**（我的决定：小模型输出 JSON 容易出错；分开请求更稳，并发可以把时间补回来）。

**系统提示词**以用户 2026-11-27 刚改好的 MDC 提示词为底，做两处调整：

- **人名改成按对照表输出中文写法**，不再保留日文。这样标题里的人名和 Jellyfin 演员、库里的演员目录一致；对照表里查不到的人名（素人昵称等）保留原文。（我的决定。原因：MDC 提示词里「保留日文」是因为拿不到演员名单，只能兜底；脚本拿得到，就用库里的正式写法。用户如果更想保留日文，改一句提示词就行。）
- 栏目名、厂牌、番号、期数保留原文；标题 30 字以内；简介去掉促销内容但不概括、不删剧情。这几条沿用 MDC 提示词。

**每次请求的用户消息**带上：

- 字段类型（标题 / 简介）；
- 番号；
- 演员对照：这部片 NFO 里每位演员的中文写法，以及对照表里她的日文写法和别名（`jp`、`zh_tw`、`keyword`），格式类似「麻倉憂、松山真琴 → 麻仓忧」；
- 片商（`<studio>`）、系列（`<series>`，有才带）；
- 待翻译的原文。标题去掉开头的番号；简介里的 `<br>` 换成换行。

### 5.4 检查模型输出

有下列任何一种情况，这个字段就算失败，保留旧译文，在报告里标出原因：

- 输出为空，或者去掉空白后不到 2 个字；
- 以「标题」「简介」「翻译」「Title」等字样开头，带冒号；
- 含有 `<think>`，或者常见的拒绝话术（「抱歉」「无法」「I cannot」等，名单由实施者定）；
- 假名占比超过 15%（说明没翻）；
- 标题超过 60 个字（要求是 30 字，给一倍余量）；
- 简介长度不到原文的 20%，或者超过 3 倍。

通过检查的输出要统一清理：去掉首尾引号和空白；简介里的换行换回 `<br>`。

### 5.5 写回 NFO

- **只改三个标签**：`<title>`、`<outline>`、`<plot>`。其他内容逐字节不变，包括 `<originaltitle>`、`<sorttitle>`、`<originalplot>` 和缩进。做法是按文本定位这三个标签替换内容，**不用 XML 库重新序列化整份文件**（重新序列化会改掉 CDATA、缩进和属性顺序）。
- **新标题** = 原 `<title>` 的番号前缀 + 空格 + 译文 + 原 `<title>` 末尾的 ` cdN`（有才加）。番号前缀和分段后缀从原 `<title>` 里取，不从别处拼，保证和 MDC 的格式一致。番号前缀就是 NFO 里 `<num>` 的原样文本：有些番号本身带空格或日文（例如 `2017-11-18 MIDE-488 新人！…`），不能按第一个空格切。`<title>` 不以 `<num>` 开头的，这个 NFO 的标题跳过不写，记录原因。原标题去番号前缀也用同样的办法。
- **新简介** = 译文 + `<br>  <br>由 <模型名> 提供翻译`；`<outline>` 写同样的内容。
- 只翻了标题、没翻简介时，简介不动；反过来也一样。
- **写之前**：核对文件内容和 `translate` 时记录的哈希一致；不一致说明期间被 MDC 或别人改过，跳过并在结果里记下。
- **写的方式**：先在同一目录写临时文件，检查能被 XML 解析，再改成原文件的属主和权限，最后原子替换原文件。

### 5.6 备份、记录、还原

- `apply` 替换每个 NFO 前，把原文件复制到 `data/nfo_retranslate/<运行编号>/backup/<相对路径>`。
- 每个 NFO 的写入结果逐行记进 `apply.jsonl`：路径、写了哪些字段、跳过原因、Jellyfin 刷新结果。
- `restore` 用备份覆盖回去（同样做哈希检查和原子替换），然后刷新 Jellyfin，并从「已写入」记录里删掉对应条目。

### 5.7 Jellyfin 刷新

- 用 18x 的 `jellyfin_media_items` 表，按 STRM 路径找 `jellyfin_item_id`。路径用 18x 扫描记录里的只读挂载路径。
- 一组内多个 NFO 对应同一个 Jellyfin 条目的，只刷新一次。
- 每个条目调用 `POST /Items/{id}/Refresh`，参数为 `MetadataRefreshMode=FullRefresh`、`ReplaceAllMetadata=true`、`ReplaceAllImages=false`。试跑已验证：只有这样才能清掉 Jellyfin 里残留的旧简介，默认扫描不会清。
- 在 `JellyfinClient` 上新增一个刷新单个条目的方法，和现有的 `refresh_library` 放在一起。
- 刷新失败不回滚 NFO，只记录下来。找不到条目 ID 的，在最后统一提示一次，可以用库扫描兜底。
- 刷新并发要低（实施者定，建议 2），避免 Jellyfin 卡住。

### 5.8 报告

`translate` 结束时生成 `report.html`，自包含单文件，放在运行目录下。用户用浏览器打开（宿主机路径 `/mnt/user/docker1/18xv2/data/nfo_retranslate/<运行编号>/report.html`，可以 scp 到本机看）。

- 每部片一行：番号、演员、字段、日文原文、旧译文、新译文、检查结果。失败的标红，并写明原因。
- 顶部是汇总：多少部、多少字段、成功多少、失败多少，各种失败原因的数量。
- 报告里不出现接口地址和密钥。

运行目录里同时保存 `translations.jsonl`（每个字段一行，含原文、旧译、新译、NFO 路径和哈希），供 `apply` 使用。

### 5.9 配置

新增几个 `.env` 配置，在 `app/core/config.py` 里按现有写法加字段：

| 变量 | 说明 |
|---|---|
| `NFO_TRANSLATE_API_BASE` | OpenAI 兼容接口地址，例如 `https://<域名>/v1` |
| `NFO_TRANSLATE_API_KEY` | 密钥。只放生产 `.env` |
| `NFO_TRANSLATE_MODEL` | 模型名，例如 `qwen38` |
| `NFO_TRANSLATE_ROOT` | 302porn_tv1 的可写根目录。生产：`/mnt/cache/docker1/alist-strm/video/302porn_tv1` |
| `NFO_TRANSLATE_MDC_DB` | MDC 数据库路径，默认 `/app/mdc/mdc_ng.db` |
| `NFO_TRANSLATE_NAME_MAP` | 演员对照表路径，默认 `/app/mdc/mapping_actor.xml` |

只读路径（换算 Jellyfin 条目用）沿用现有的 `MEDIA_LIBRARY_STRM_ROOTS`。缺必要配置时直接报错退出，不猜默认值。

## 六、测试

后端单元测试放在 `tests/`，在 Spark 上跑。至少覆盖：

- **NFO 替换**：用真实格式的样例 NFO（脱敏），替换后除三个标签外逐字节不变，并且能被 XML 解析；CDATA 里本身带 `]]>` 的情况要能正确处理。
- **标题重组**：番号前缀、`cdN` 后缀、带「-C」「-破解」等后缀的文件名。
- **范围判断**：中文站来源跳过；原文没有假名跳过；分段子任务按主任务算；找不到任务时按简介标记判断；找不到任务的 NFO 超过 100 个时不加 `--force` 就退出；「已写入」记录里哈希没变的跳过，加 `--redo` 不跳过。
- **分组**：同目录、同番号的多个 NFO 归为一组；组内字段来源不一致时，只写自身在范围内的 NFO；硬链接数大于 1 的跳过。
- **番号前缀**：`<num>` 带空格或日文时也能正确截取；`<title>` 不以 `<num>` 开头时跳过。
- **对照表解析**：`keyword` 里的别名拆分；查不到的人名不出现在参考信息里。
- **输出检查**：每种失败规则至少一个样例。
- **写入保护**：哈希不一致时跳过；写入后属主和权限与原文件一致（用临时目录测）。
- **模型调用**：用假的 HTTP 传输层测重试、超时、并发上限，不访问真实接口。

## 八、风险

- **MDC 重试会覆盖**：用户已接受。使用说明里要写明。
- **模型质量不稳**：靠输出检查和「先报告后写入」兜底。整体效果不好，就不 `apply`，或者 `restore`。
- **和 MDC 同时写同一个 NFO**：靠写入前的哈希检查跳过。
- **Jellyfin 强制刷新的副作用**：`ReplaceAllMetadata` 会让 Jellyfin 按 NFO 重建这个条目的元数据，冲掉 NFO 以外的修改。已核对，可以直接用：
  - 2026-11-27 查 Jellyfin 库：「115番号」5524 部电影，整条锁定 0、锁定字段 0；强制排序名来自 NFO 的 `<sorttitle>`，重读后不变。
  - 用户确认没有在 Jellyfin 网页上手动改过这个库的条目。
  - 18x 的显示名只作用于本地库，合集成员关系不在电影条目上。
