# 整站 UI 重设计与下载器页重做设计

日期：2026-10-31（修订于 2026-11-01）  
范围：设计系统与外壳（阶段 A）、下载器页重做（阶段 B）、其余页面迁移（阶段 C），一起交付、分阶段实施。

## 背景与问题

用户反馈 4 个问题：

1. 下载器候选表把大小直接显示为原始字节（如 `12948331 bytes`）。
2. 「待确认候选（50）」信息不足：没有资源日期、进度、状态；`outdated`、`stable`、`never` 等英文状态语义不清。
3. 下载任务列表只是把 RN 任务拉回来：看不到任务大小、下载时间，不能筛选和回看下载记录。
4. 全站 UI 显脏：紫灰大色块、装饰底纹、多余的「Admin workspace」标题，右上角用户名被包在圆圈胶囊里。

现状事实（已核对代码）：

- `downloader_packages` 已保存 `published_at`、`known_total_size`、`media_count`、`current_download_status`，前端未使用或未格式化。
- RN `current_download_status` 取值：`never`、`queued`、`downloading`、`completed`、`outdated`、`failed`、`cancelled`。`outdated` 的含义是「该资源包曾成功下载，之后又被扫描追加了新媒体（新 `index_revision`）」。
- RN 任务详情返回 `created_at`、`updated_at`（Unix 秒浮点数），文件级返回 `total_size_bytes`、`downloaded_size_bytes`、`status`、`error`。18x 目前只把它们留在 `raw_payload_json` 里，没有结构化字段，所以无法排序和筛选。
- 候选状态 `dismissed` 已存在，但只用于「旧版本候选被新版本替代」，没有用户入口。
- 前端技术栈：React 19 + antd 6 + Vite。主题通过 `frontend/src/theme/palettes.ts`、`antdTheme.ts` 和 `index.css` 的 CSS 变量实现，有「护眼 comfort / 墨灰 graphite」两套主题。

## 核心设计哲学与决策

针对用户提出的核心要求：**样式美观、风格统一、交互直接、少跳转、信息密度有层次**，确立以下设计准则：

| 维度 | 设计决策 | 原理与目标 |
|------|----------|------------|
| **视觉基调** | 现代化工匠风格（Modern Minimalist / Linear 质感） | 中性冷灰背景 + 严谨蓝色主色 + 精致微投影与柔和半透明磨砂，告别纯白板死灰线条，提升呼吸感与专业质感。 |
| **交互心智** | 双流模型（Two-Stream Model）：候选收件箱 + 任务看板 | 消除旧版“待确认 -> 已提交 -> 下载记录 -> 已忽略”4 个 Tab 的频繁横跳。将流程收敛为“选品决策”与“进度监控”，零跨页跳转。 |
| **就地处理** | 秒级撤销（Undo Toast）与侧边检查抽屉（Slide-over Inspector） | 忽略操作支持 5 秒内原地撤销；任务详情与失败文件在侧边抽屉就地查看与重试，主表格永远不失焦、不重构。 |
| **信息密度** | 主次复合单元格排版（Compound Cells）与悬停动作 | 将 8~9 列的横向膨胀表格压缩为 4~5 个高内聚复合列，主信息高对比突出，次要信息微弱化，消除 Z 型视线横扫疲劳。 |
| **下载记录筛选** | 状态、时间、频道/关键词、标题搜索全覆盖 | 顶部提供紧凑指标条，支持全量组合检索。 |
| **其余页面迁移** | 换皮 + 统一骨架组件 | 保持既有业务功能和接口不动，只升级视觉令牌与交互骨架。 |

#### 视觉法则（The Visual Rules）

1. **告别粗糙扁平，引入精细微投影（Micro Elevation）**：
   - 卡片与面板不再使用生硬纯黑灰死线，采用精密复合微阴影：
     ```css
     box-shadow: 0 1px 3px 0 rgba(0, 0, 0, 0.03), 0 0 0 1px var(--app-border);
     ```
   - 抽屉与浮动操作条采用浮升投影：
     ```css
     box-shadow: 0 10px 25px -5px rgba(0, 0, 0, 0.1), 0 8px 10px -6px rgba(0, 0, 0, 0.08);
     ```
2. **柔和微徽章（Soft Tinted Badges）**：
   - 状态 Tag 统一采用 4px 微圆角、`padding: 2px 8px`，背景为 8%~12% 语义透明底色，文字为对应深色实体字，彻底去除旧版刺眼粗糙的大色块。
3. **圆角与间距系统**：
   - 按钮/输入框：6px。
   - 卡片/表格容器：8px。
   - 底部浮动胶囊/标签徽章：12px / 999px（Pill）。
4. **极致克制的动效**：
   - 浮动条与抽屉滑出保持 150ms~200ms cubic-bezier(0.16, 1, 0.3, 1) 缓动，遵守 `prefers-reduced-motion`。

### 字体与格式规范

- 字体栈：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Noto Sans SC', 'Segoe UI', sans-serif`。
- 数字列、时间与容量强制声明：`font-variant-numeric: tabular-nums`，确保表格竖向数值整齐划一。
- 格式化工具集（集中于 `frontend/src/utils/format.ts`）：
  - `formatBytes(bytes)`：智能转为 B / KB / MB / GB / TB，保留 1 位小数；0 或无效值显示 `-`。
  - `formatShortDateTime(value)`：今年内显示 `10-28 14:05`，跨年显示 `2025-10-28`，鼠标悬停展示完整本地 ISO 时间。
  - `formatRelative(value)`：输出「3 分钟前」「2 天前」。
  - `formatDuration(seconds)`：输出「1 小时 12 分」「45 秒」。

### 外壳组件（AppShell）

- **侧栏（Sidebar）**：
  - 白色/深灰表面 + 右侧 1px 微边框。
  - 分组文案中文化：`Data → 数据`，`Workflow → 流程`，`System → 系统`。
  - 选中项使用淡蓝底色（`--app-brand-subtle`）与蓝色文字，高亮条厚度 2px。
  - 品牌标识改为纯文字排印「18x 整理台」，移除旧版多余的色块方标。
- **顶栏（Header）**：
  - 移除多余的「Admin workspace / 18x 管理台」大标题。
  - 左侧展示极简的面包屑：`分类 / 当前页面`。
  - 右侧仅保留用户菜单：纯文字「用户名 ▾」，移除旧版胶囊边框。下拉菜单整合「外观（浅色 / 深色切换）」与「退出登录」。

## 阶段 B：下载器页重做（Downloader Overhaul）

### 架构革新：告别 4-Tab，采用「双流模型」

页面由原先割裂的 4 个标签页重塑为 **2 个核心主视图**，彻底终结跨页跳转：

```
┌─────────────────────────────────────────────────────────────┐
│ 📥 候选收件箱 (38 待确认)        ⚡ 任务看板与历史 (2 活跃)  │
└─────────────────────────────────────────────────────────────┘
```

1. **【候选收件箱（Candidates Inbox）】**：专注资源筛选决策（下还是不下）。
2. **【任务看板与历史（Tasks & History）】**：专注下载进度监控与历史归档（正在下什么、以前下了什么）。

当前活动标签页同步至 URL 查询参数 `?view=inbox|tasks`，支持刷新与书签直达。

### 视图一：候选收件箱（Candidates Inbox）

#### 1. 顶部轻量分段与工具栏
- **左侧内联分段控制器（Segmented Pill）**：
  - `待确认 (42)` | `已忽略 (6)`
  - 点击就地切换列表内容，**无需跳转到独立页面**。
- **右侧过滤区**：
  - 标题快速搜索（带清除图标与快捷键 `/` 聚焦）。
  - 白名单命中词下拉筛选。
  - 下载状态筛选：`全部 / 未下载 / 有更新 / 曾失败`。

#### 2. 高内聚「主-次复合单元格」排版表格
将旧版的 8 列臃肿表格压缩为 **5 个高清晰度核心列**，消除眼球水平扫视疲劳：

| 列名 | 单元格复合排版结构 | 说明 |
|------|-------------------|------|
| **选择** | `[  ]` 复选框 | 支持 Shift 连选，首行带全选。 |
| **资源包与来源** | **第一行（主）**：`资源包标题`（加粗 14px，支持单行溢出省略）<br>**第二行（副）**：`<频道徽标>` `#{远端ID}` · 命中白名单 `<淡蓝小胶囊>` | 主信息抓人，副信息暗化，关联一眼可知。 |
| **体量与发布** | **第一行（主）**：`2.4 GB` · `18 媒体`（Tabular-nums）<br>**第二行（副）**：`3 天前`（悬停展示具体发布时间） | 容量与数量直接关联，时间辅助决策。 |
| **版本与状态** | `<StatusTag>`：<br>• 未下载（微灰）<br>• 增量更新 `<AmberTag>有更新 (+3)</AmberTag>`<br>• 曾失败（柔红） | 悬停“有更新”直接展示差异详情：`本地已完成 r2，远端新版 r5`。 |
| **操作** | 默认半隐，**鼠标悬停该行时浮现（Hover-to-reveal）**：<br>`[忽略]` 按钮 | 保持常规浏览时的视觉呼吸感，避免满屏按钮噪音。 |

#### 3. 悬浮批量操作条（Floating Action Bar）
当用户勾选 ≥ 1 个候选时，页面底部中央丝滑浮现半透明磨砂胶囊底栏：
- **外观**：居中悬浮，`bottom: 24px`，圆角 12px，背景 `rgba(255, 255, 255, 0.85)`（深色 `rgba(31, 41, 55, 0.85)`）+ `backdrop-filter: blur(16px)` + 浮升阴影。
- **内容**：
  - 左侧：`已选 12 项 (共 8.4 GB)` · `[全选当前页]` · `[清空]`
  - 右侧：
    - `[忽略所选]`（次级描边按钮）
    - `[确认下载 12 个 (Enter)]`（主品牌高亮按钮）
- **操作反馈与极速微交互**：
  - 点击「确认下载」后，选中的行产生柔和淡出动画，底栏收起，右下角弹出成功通知，用户继续留在当前页面处理剩余内容。

#### 4. 原地秒级撤销机制（In-place Undo Toast）
- 无论是单行点击「忽略」还是批量「忽略所选」，**均无需前往“已忽略”页面**。
- 界面底部右下角立即弹出轻量 Toast：  
  `已忽略《xxx》等 3 个资源包  [撤销操作 (5s)]`
- 用户手滑误触，点击 `[撤销]` 即可在 5 秒内原地无损恢复；5 秒后自动提交持久化。
- 如需长期回溯已忽略的项，点击顶部切换到 `已忽略 (6)` 视图，列表中每行提供 `[恢复]` 按钮。

### 视图二：任务看板与历史（Tasks & History）

将原设计分散的“已提交”与“下载记录”完全熔炼为一体，呈现一体化下载流水线。

#### 1. 顶部活跃任务与状态条（Pinned Active Tasks）
- **页头状态指示**：RN 服务连通状态（带微光绿点 / 红点）、上次同步时间（相对时间）、`[暂停全部]` / `[恢复全部]`、`[同步资源包]`。
- **活跃任务摘要条**：若当前有任务正在进行（`downloading`）或排队（`queued`），在表格上方置顶显示紧凑进度行：
  - 任务名、实时下载速率（如 `18.5 MB/s`）、整体动态进度条、活跃文件数。

#### 2. 宏观统计与筛选工具栏（Metric Strip & Toolbar）
- **紧凑统计条**：今日已下（数量与容量）· 近 7 天总量 · 进行中任务数 · 近 7 天失败文件数。
- **多维组合筛选**：
  - 状态选择：`全部 / 活跃中 / 已完成 / 部分完成(有报错) / 失败 / 已取消`。
  - 时间跨度：`今天 / 近 7 天 / 近 30 天 / 自定义`。
  - 频道快速下拉、白名单命中关键词、标题实时过滤。

#### 3. 任务主表格（纯粹宏观视图）
表格专注于“任务级别”的表现，不再因为文件报错而把行结构突变为文件列表：
- **字段**：任务标题/所属频道、状态标签（`StatusTag`）、文件进度（进度条 + 成功/失败/总数）、传输量（已下 / 总容量，带百分比）、启动时间与耗时、操作（`[重试失败项]`、`[取消]`）。
- **点击任意任务行**：直接打开侧边检查抽屉（Slide-over Inspector）。

#### 4. 零跳转详情：侧边检查抽屉（Slide-over Inspector）
彻底取代原设计的“行内展开大表格”与“破坏主表的失败文件视图切换开关”。点击任务后，右侧平滑滑出 560px 抽屉：

```

│  任务详情: 某写真集全集汇总           [重试失败] [×]│
│  状态: 部分完成  │  耗时: 12 分 34 秒  │ 7.8/8.2 GB│

│  ⚠️ 失败文件预警 (2 个文件下载异常)                  │
│  ┌────────────────────────────────────────────┐  │
│  │ 003.jpg · 24.2 MB                          │  │
│  │ 错误: Connection reset by peer   [单项重试] │  │
│  └────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────┤
│  文件清单 (共 142 个)        [🔍 搜文件名] [全部▼]│
│  • 001.jpg · 18.5 MB · [已完成]                  │
│  • 002.jpg · 21.0 MB · [已完成]                  │
│  • 003.jpg · 24.2 MB · [失败]                    │
├──────────────────────────────────────────────────┤

└──────────────────────────────────────────────────┘
```

- **第一层（顶部看板）**：任务全局吞吐量、总时间、关联的原始资源包标题与频道，提供「重试全部失败文件」主按钮。
- **第二层（失败聚焦区）**：若该任务存在失败文件，**自动置顶高亮告警卡片**，清楚列出失败原因（网络超时、存储受限等）与单个重试按钮。
- **第三层（全量文件列表）**：虚拟长列表，支持在抽屉内实时输入文件名过滤、按状态（仅看失败/仅看成功）快速切片。
- **体验优势**：主表格无需重绘，不发生任何 URL 或 Tab 跳转，按 `Esc` 或点击遮罩即收起抽屉，上下文零丢失。

### 状态中文映射与语义规范

#### 1. 资源包下载状态（`current_download_status`）

| 原值 | 中文文案 | 视觉呈现 | 语义与场景 |
|------|----------|----------|------------|
| `never` | 未下载 | 灰底深灰字 | 从未加入过下载队列的全新资源包。 |
| `queued` | 排队中 | 蓝底深蓝字 | 已提交到 RN，等待空闲下载槽位。 |
| `downloading` | 下载中 | 蓝底发光/呼吸徽标 | 正在传输数据。 |
| `completed` | 已下载 | 柔绿底深绿字 | 本地版本与远端版本完全一致且下载成功。 |
| `outdated` | **有更新 (+N)** | **醒目琥珀底色** | 曾下载成功，远端追加了 N 个新媒体文件（悬停提示增量详情）。 |
| `failed` | 下载异常 | 柔红底深红字 | 上次下载整体失败或中断。 |
| `cancelled` | 已取消 | 灰底字 | 用户主动取消的任务。 |

#### 2. RN 任务运行状态（`task_state`）

- `pending` / `queued` → **排队中**（浅蓝）
- `running` / `downloading` → **下载中**（主蓝）
- `completed` → **已完成**（柔绿）
- `completed_with_errors` → **部分完成**（琥珀色，提示有失败文件可重试）
- `failed` → **失败**（柔红）
- `cancelled` → **已取消**（中性灰）
- `paused` → **已暂停**（黄色）

### 后端改动与接口演进

数据库与接口逻辑完全对齐双流模型与侧边抽屉需求。

#### 1. 数据库迁移（Alembic）
只新增字段与索引，不破坏既有数据：

`downloader_packages` 新增：
- `ignored_at`：带时区的时间戳，为空表示未忽略。
- `ignored_reason`：文本，记录忽略备注。

`downloader_task_snapshots` 新增：
- `remote_created_at`：带时区时间，从 RN `created_at`（Unix 秒）转换。
- `remote_updated_at`：带时区时间。
- `finished_at`：带时区时间，任务首次到达终态时记录。
- `total_bytes`、`downloaded_bytes`：BigInteger，默认 0。
- `channel_title`：文本，关联资源包的频道名。
- 复合索引：`(node_key, remote_created_at)`、`(node_key, status)`。
- 迁移内脚本：安全回填已有快照中的时间和求和字节数。

#### 2. 同步与业务服务（`sync_service.py`）
- `sync_tasks`：提取并持久化上述结构化字段。
- `sync_packages`：跳过 `ignored_at` 非空的包，防止重新生成候选；现有待确认候选自动标记为 `dismissed`（`dismissed_reason='ignored'`）。

#### 3. API 路由规范（`/downloader` 前缀）
- `GET /downloader/packages`：
  - 参数：`view`（`candidates` 待确认 / `ignored` 已忽略）、`download_status`、`search`、`sort`、`page`、`page_size`。
  - 响应：包含 `published_at`、`known_total_size`、`new_media_count` 等复合排版所需字段。
- `POST /downloader/packages/ignore`：
  - 请求体：`{ candidate_ids: [...], reason?: string }`。
- `POST /downloader/packages/unignore`：
  - 请求体：`{ package_ids: [...] }`，清除忽略并立即触发白名单比对。
- `GET /downloader/tasks`：
  - 统一支持：`status`（逗号分隔）、`since`、`until`、`channel`、`keyword_entry_id`、`search`、`page`、`page_size`。
- `GET /downloader/tasks/{task_id}/detail`：
  - 为**侧边检查抽屉**提供轻量数据支撑：返回任务聚合状态、失败文件优先列表、全量文件分页/列表。
- `POST /downloader/tasks/{task_id}/retry`：支持传入 `{ only_failed: true }` 仅重试该任务下的失败文件。
- `GET /downloader/summary`：提供顶部紧凑统计条数据。

## 错误处理与容灾边界

- **RN 服务异常感知**：RN 掉线或响应超时时，顶栏状态点显示红色，并在操作区提示具体网络或鉴权错误；用户仍可正常检索本地已同步的历史数据。
- **撤销超时容错**：Toast 撤销基于前端乐观回退（Optimistic Rollback），5 秒内若用户撤销，取消定时提交；即使网络抖动导致服务端已标记，恢复接口具备幂等性，不产生数据脏读。
- **空值防御**：缺失容量或时间字段时显示 `-`，数字对齐不受影响。

## 总结：新旧设计体验对比

| 体验维度 | 旧设计 / 原初稿 | 本次重构设计 |
| :--- | :--- | :--- |
| **页面跳转** | 4 个独立 Tab，已提交还要跳到下载记录 | **双流模型，0 跨页跳转**；抽屉就地查看，Toast 就地撤销 |
| **表格扫视** | 8~9 列松散排列，横向拉扯眼球 | **5 列高内聚复合单元格**，主次分明，信息高密度有呼吸感 |
| **视觉质感** | 扁平死灰线框或大紫大黑块 | **现代工匠风**：精细微投影（Micro Elevation）+ 半透明磨砂底栏 |
| **操作噪音** | 每行平铺操作按钮，满屏杂乱 | **悬停显现（Hover-to-reveal）**，常态清爽，交互即时敏捷 |
| **容错体验** | 忽略后必须换页面翻找找回 | **5 秒 Toast 原地撤销**，误触极速复原 |
