# 2026-11-01 p115client 间接依赖版本漂移修复

## What was done

- 复现：在 Spark（ARM64 Linux）上用全新 Python 3.12.16 按 `main` 的 `pyproject.toml` 执行 `pip install -e ".[dev]"`，`import p115client` 报 `ImportError: cannot import name 'to_list' from 'asynctools'`。当时装到的是 `python-asynctools 0.2.2`（2026-07-15 发布，删掉了 `to_list`）。
- 根因：`p115client==0.0.9.3.6` 本身固定了，但它的约 36 个间接依赖（同一作者的小库）只写下限。7 月中旬以后这些库成组升级：asynctools 0.2.x、iterutils 0.3.x、concurrenttools 0.1.9、p115oss 0.1.2 互相要求新版本。只把 asynctools 降到 0.1.x 不行——新版 iterutils 又要 `iter_async`，pip 也报依赖冲突。
- 方案：不升级 p115client（避免 115 接口行为变化），而是把它的同作者间接依赖全部锁到 p115client 固定当天（2026-07-03）的版本。版本来自 `uv pip compile --exclude-newer 2026-07-04` 的解析结果。主流第三方库（orjson、yarl、urllib3-future 等）不锁。
- 先把本工作区分支快进到 `main`（bfba5b74）：原分支基于 `feat/conflict-resolution`，落后 `main` 108 个提交，上面仍是 `p115client>=0.0.8.4.4`；生产部署分支是 `main`。

## Testing

- 全新 Python 3.12 venv 安装后：`pip check` 无冲突；`p115client` 全部子模块都能导入；`P115OpenClient` / `P115Client` 上项目用到的方法都在（磁力下载走备用方法名 `clouddownload_task_add_urls_open`，也存在）；`app.services.client_115.client` 拿到的 `P115OpenClient` 不是 None。
- `docker build -f docker/Dockerfile`（Spark，arm64）退出码 0；容器内同样的检查脚本输出 CHECK OK，`pip check` 无冲突。
- 后端全量：`pytest tests -q -n 16`（Spark，Python 3.12 + 新依赖）→ 359 passed，52.6 秒。
- 日志：Spark 上 `~/ci/18x_v2/docker-build.log`、`~/ci/18x_v2/pytest.log`。
